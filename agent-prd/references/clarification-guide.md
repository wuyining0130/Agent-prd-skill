# Agent PRD 澄清问题库

本文件定义了 Phase 2 澄清对话的问题清单、选项设计原则和分支逻辑。

---

## 设计原则

1. **每轮一个问题**，附带 2-4 个选项 + 自由输入
2. **先必问后按需**，根据项目复杂度决定是否追问
3. **选项即引导**，选项本身帮助用户思考维度
4. **通常 4-8 轮结束**，复杂场景可增加，但不为凑轮次而提问

---

## 必问问题（Q1-Q7）

### Q1. 项目命名与场景

**目的**：锁定 Agent 做什么、给谁用

> 先帮这个 Agent 起个名字吧——它主要负责什么工作？给谁用的？

选项示例（根据用户描述动态生成）：
- "{用户提到的场景} Agent" — 面向 {角色}
- 自定义命名

**追问**：如果用户描述模糊，追问"能描述一个典型的使用场景吗？"

---

### Q2. 当前人工流程与痛点

**目的**：理解 as-is，定位自动化价值

> 现在这件事是谁在做？大概的流程是怎样的？最让人头疼的环节是？

选项示例：
- 完全人工操作，流程固定但重复性高
- 有部分自动化（脚本/工具），但关键决策仍靠人
- 流程因人而异，缺乏标准化
- 其他

**追问**：痛点定位——"如果只能解决一个问题，你最想自动化哪个环节？"

**落位提醒**：Q1/Q2 中关于“给谁用、典型场景、当前方式、痛点”的信息，默认合并写入 `1.1 背景与目标`；除非用户明确要求，否则不再单列 `1.2 用户角色与使用场景`。

---

### Q3. 知识与数据来源

**目的**：明确 Agent 的"知识底座"——它需要学会什么才能做好这件事

> Agent 要做好这个工作，需要掌握哪些知识？比如业务规则、历史案例、参考文档？这些知识现在在哪里？

选项示例：
- 业务规则文档（SOP、政策、规范）
- 历史案例/记录（过去人是怎么处理的）
- 专家经验（在老员工脑子里，没有文档化）
- 外部参考资料（行业标准、竞品做法）

**追问**：
- "这些知识有现成的文档吗，还是需要从老员工那里整理？"
- "有没有带标注的历史数据？比如过去处理的案例和结果？大概多少条？"
- "知识更新频率如何？业务规则经常变吗？"
- "这些知识后面准备怎么落地：哪些写成提示词原则，哪些写成结构化配置，哪些必须做硬校验？"

**边界提醒**：这里问的是“长期可复用的知识和离线对齐数据”，不是每轮任务启动时去查的实时报表、事件或配置值；前者回答“Agent 需要知道什么”，后者回答“当前这一轮发生了什么”，后者统一放到 2.3 Perception。

---

### Q4. Agent 角色与成功定义

**目的**：定义 Persona 和成功标准

> 如果把 Agent 想象成一个新员工，它的岗位是什么？什么算"干得好"？

选项示例：
- 效率优先——"比人快 X 倍，准确率不低于 Y%"
- 质量优先——"准确率/一致性必须高于人工"
- 覆盖优先——"7×24 不间断处理，人力补充"
- 成本优先——"单笔处理成本降到 ¥X 以下"

**追问**："有没有一个具体的数字目标？比如准确率 ≥ 90%、日处理量 ≥ 1000 单？"
**补充追问**：
- "安全性、正确性、覆盖率、解释性，谁优先？"
- "Agent 允许输出哪些终态：动作建议、观察复查、请求人工确认、无动作？"
- "缺配置、缺数据或低置信度时，默认该怎么退化？"

---

### Q5. 日常工作流程

**目的**：拆解 Agent 一次完整任务的过程

> 描述一下 Agent 日常工作的一个完整循环——从收到什么信号开始、中间要看什么想什么、最后做什么？

选项示例（根据 Agent 类型动态）：

**对话交互型**：
- 用户发消息 → 理解他想干嘛 → 查信息 → 回复
- 用户上传文件 → 解析内容 → 生成分析报告

**后台决策型**：
- 定时看数据 → 发现异常 → 自动调整 → 通知人
- 接到事件 → 判断要不要处理 → 执行动作

**工作流编排型**：
- 接到大任务 → 拆成小步骤 → 分别执行 → 汇总结果

**追问**：
- "一个循环大概多长时间？几秒钟还是几小时？"
- "同时可能有多少个任务在跑？"
- "这份文档后续主要用于评审，还是会直接拿去开发 / vibecoding？如果要直接开发，第二章需要写到模块边界、输入输出和端到端运行时序。"

---

### Q6. 工具与 API 依赖

**目的**：明确 Action 层能力

> Agent 执行动作时，需要调用哪些外部系统或工具？

选项示例：
- 内部业务系统 API（CRM、ERP、OA 等）
- 第三方平台 API（广告平台、支付、物流等）
- 数据库读写（直接查询/写入）
- 通知渠道（邮件、钉钉、企微、短信）

**追问**：
- "这些 API 现在有现成的吗，还是需要新开发？"
- "有没有权限限制或调用频率限制？"

---

### Q7. 边界与安全

**目的**：定义 Guardrails

> Agent 有哪些事情是绝对不能做的？出问题时怎么兜底？

选项示例：
- 金额/权限类——超过 ¥X 必须人工审批
- 不可逆操作——删除/发布/转账前必须确认
- 合规红线——不能接触 PII/不能给出承诺性结论
- 质量兜底——置信度低于 X% 时升级给人

**追问**：
- "有没有需要人机协同的环节？什么时候必须人来拍板？"
- "如果 Agent 连续犯错，有没有熔断机制？"

---

## 按需问题（Q8-Q10）

### Q8. 评测方案（项目有明确质量要求时问）

**触发条件**：用户在 Q4 提到了具体数字目标，或业务本身高风险

> 你打算怎么验证 Agent 做得对不对？有没有现成的测试数据？

选项示例：
- 有历史数据可做回测（过去 X 个月的记录）
- 需要人工标注一批测试集
- 先小范围灰度，对比 Agent vs 人工
- 还没想好，需要建议

---

### Q9. 记忆与进化（长周期/多轮交互场景时问）

**触发条件**：Agent 类型为对话交互型，或业务需要跨会话上下文

> Agent 需要"记住"什么？要不要随着使用越来越聪明？

选项示例：
- 需要记住用户偏好/历史操作
- 需要积累业务知识（如常见问题、最佳实践）
- 不需要长期记忆，每次独立执行即可
- 需要定期更新策略（如跟随市场变化）

---

### Q10. 约束条件（有明确技术/商务限制时问）

**触发条件**：用户提到了预算、延迟要求、合规要求

> 有哪些硬性限制需要考虑？

选项示例：
- 延迟敏感——必须在 X 秒内响应
- 预算有限——单次调用成本 ≤ ¥X
- 合规要求——数据不能出境/必须脱敏
- 并发要求——需要支持 X 并发

---

## 分支逻辑

```
开始
├── Q1（必问）
├── Q2（必问）
├── Q3（必问）——注意：问的是知识/训练数据，不是运行时输入
├── Q4（必问）
├── Q5（必问）
├── Q6（必问）
├── Q7（必问）
├── Q8（如果 Q4 有数字目标 OR 高风险业务）
├── Q9（如果 Agent 是对话交互型 OR 长周期任务）
└── Q10（如果用户提到预算/延迟/合规）
```

## 结束判断

满足以下条件时结束澄清：
1. 必问问题（Q1-Q7）全部有答案
2. 按需问题根据触发条件已覆盖
3. 没有明显的信息缺口（四大章节每个都有输入）

结束时告知用户："信息收集完毕，接下来我会生成 Agent PRD 文档。"

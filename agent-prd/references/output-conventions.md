# 产物命名与旧文件兼容

> 本文件摘录自当前配套 conventions skill 的第 5.1 节，供 agent-prd 独立安装时读取。表中其他产物用于解释兼容命名，不代表本 skill 会生成这些产物。Agent PRD 的输出位置遵循 SKILL.md 或用户指定路径。

所有新建的需求级文档和原型统一使用“需求名称中文产物类型.扩展名”，需求名称与产物类型直接连写，不添加括号、空格、短杠或其他分隔符。本约定中的 `{模块名}` 即已确认的需求名称，与 `requirements/{模块名}/` 的目录名保持一致；独立 Agent PRD 使用 `{需求名称}`，优先取用户确认名称，其次取已有文档的需求名称，不使用“requirements”等通用父目录名代替。名称未明确时，在原有澄清环节确定。

| 产物 | 新建时的标准相对路径 | 旧名称（仅用于兼容查找） |
|---|---|---|
| PRD | `{模块名}需求文档.md` | `prd-draft.md` |

路径解析与维护规则：

兼容查找包含此前的“需求名称（产物类型）.扩展名”中文括号形式和“需求名称-产物类型.扩展名”短杠形式；不因换样式另建同用途副本。日期用于区分历史报告时直接接在产物类型后，例如 `需求名称代码审查报告2026-09-20.md`；日期内部保留标准短杠。名称中的原有文字、目录结构和扩展名保持不变。

1. 用户明确指定的文件路径优先；未指定时按本表查找标准路径，再查对应旧路径。所有新建／修改判定、PRD 守护、评审门禁、原型选择都使用解析后的实际路径，不能只检查新文件名。下游查找 PRD 时同时识别 `{模块名}需求文档.md` 与 `{需求名称}Agent需求文档.md`；已知 `mode: agent-prd` 时使用 Agent需求文档，两者并存时按第 3 条确定权威版本，不改变原文档的业务结构。
2. 仅存在旧文件时，读取或修改该文件并沿用原路径，不自动改名、不另建同用途副本。旧文件缺失的其他产物若需首次生成，采用新名称。保留历史产物，无需批量迁移。用户明确要求迁移时可以重命名，并同步本地链接、来源记录和项目指引，不改变业务版本。
3. 新旧文件同时存在时，核对上游溯源和需求上下文，使用已有明确指定的权威文件；无法确定或内容冲突时请用户选择，不仅按文件名或修改时间自动覆盖。
4. 修改既有产物时沿用解析后的路径；首次生成或用户明确要求迁移时采用标准名称。本文及各 skill 正文中的标准文件名示例都受此规则约束。
5. 下游文档的来源路径、版本、HTML 来源注释和链接记录实际读取文件，不将旧文件路径虚写为新名称。项目 AGENTS.md／CLAUDE.md 中的产物路径指引须同时覆盖新旧名称；业务修改门禁不因改名失效。
6. 本次只调整需求级交付文件名。`requirements/`、`review/`、`prototype/`、`code-review/` 等目录、skill 名称、内部模板资源名、`coding-knowledge/` 项目知识库及 TAPD 运行时备份格式沿用原约定。PRD 的业务版本仍在文档中维护，不因采用新文件名自动改变版本规则。
